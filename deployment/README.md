# Размещение на своём сервере

Игра статическая. Корнем публичного сайта должна быть папка `dist/`, а не корень архива. Для Nginx замените путь root из примера на свой путь; настройте домен и HTTPS отдельно под инфраструктуру сервера. Файлы GLB: model/gltf-binary, JS: application/javascript, SVG: image/svg+xml, WOFF2: font/woff2, JSON: application/json, OGG/MP3: audio/ogg и audio/mpeg. Указатель dist/index.html использует относительные URL, поэтому папка сайта может иметь отдельный префикс, если все файлы сохраняют структуру.

Пример Docker (выполняется из корня проекта, требуется доступ к образу Nginx):

```
docker build -f deployment/Dockerfile -t shadow-tale:v184 .
docker run --rm -p 8080:80 shadow-tale:v184
```

Открыть http://localhost:8080. Для постоянной эксплуатации добавьте политику перезапуска, HTTPS и резервные копии под свой сервер. Этот шаблон не развёрнут и не протестирован с Docker в среде экспорта.

Не требуется перенос API-ключей, базы данных или авторизации Sites: игра использует собственные локальные файлы и localStorage. Не включайте политики Content-Security-Policy, запрещающие blob: изображения или рабочие inline-стили, без проверки GLTFLoader и UI. Сначала запустите пример с обычной политикой сервера, затем проверяйте изменения ограничений.

Проверка после переноса: все JS/CSS и запросы к GLB/текстурам/audio возвращают 200; нет ошибок WebGL/шейдеров; грузятся материалы домов, леса, персонажей; работает музыка после действия пользователя; исправно управление; окна читаются; ресурсы, восстановление, торговля, флэшбек, три боя и сохранения работают. HTTPS требуется для полноценной современной браузерной среды.

Старые сохранения экспортировать со старого адреса и импортировать на новом (tools/EXPORT-SAVE.js, tools/IMPORT-SAVE.js). Они не находятся в серверной папке.
